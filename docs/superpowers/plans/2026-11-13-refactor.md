# Layering refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make routes thin, write cross-cutting boilerplate once, point every import downhill
(routes → server → game; components → game), and enforce that with lint. Behavior does not change.

**Architecture:**

- Keep the existing three layers:
  - `lib/game`: pure rules;
  - `lib/server`: services taking `db` first and returning results;
  - thin `+page.server.ts` files.
- Pure rules now in routes move into `lib/game` with tests. Database orchestration moves into
  `lib/server`.
- Types that components need move from `lib/server` and from components into `lib/game`.
- Components are grouped into `ui/` and domain folders.

**Tech Stack:** SvelteKit 3 / Svelte 5, Drizzle + PGlite, Vitest, Playwright, typescript-eslint.

**Spec:** the owner's refactor brief (2026-11-13, in the session), plus `CONTRIBUTING.md` and
`docs/adr/`. No design spec, because behavior does not change.

## Global Constraints

- **Behavior-preserving:**
  - no copy changes (the 503 messages stay word for word);
  - no UI, route or URL changes.
- **Don't touch:**
  - `drizzle/`;
  - DB schema columns;
  - `.env*`;
  - `.claude/`, `.github/agents|skills|hooks/`, `.impeccable/`, `.superpowers/`.
- **No new dependencies.**
- **Tests:**
  - Test assertions change only mechanically (import paths, file moves).
  - Moved logic gets its tests moved first, or written first (TDD).
- **Coverage:** `src/lib/game/**` stays at 100% branches, functions, lines and statements. Every
  file moved into `game` brings tests that keep it there.
- **Server-only:** `$app/env/private` and everything in `lib/server` stay server-only.
- **Commits:** each step is one `refactor:` commit. After it, `npm run lint`, `npm run check` and
  `npx vitest --run` pass.
- **Before each PR:** also run `npm run test:coverage`, `npm run build` and `npx playwright test`.
- **Findings:** bugs found go in the Findings list, not into a fix.

## Review Focus

1. **Exact copy.** Every 503 message, `fail()` message and redirect URL is unchanged. Grep the
   old strings before and after each PR.
2. **Form whitespace.**
   - Admin trims every field.
   - The builder targets field trims.
   - Every other reader passes the raw string.
   - A shared reader must not change either behavior.
3. **The builder's step guards run in the same order:**
   1. `canOpen`, then redirect to the first open step;
   2. a size check, then redirect to `size`;
   3. `pickedHabits`, then redirect to `habits`.
   - `start` checks `draft.size` (not `card.size`).
   - `size` checks `draft.cardId` first.
   - `createHabit` and `discard` run no guard.
4. **The log JSON.** It keeps the same keys in the same order (hooks specs read it).
5. **Server-only protection through `#lib/server`.** It is proven by a build that fails, not
   assumed.

### Findings (bugs: not fixed here)

1. **The builder's board preview hardcodes `weekStartsOn: 'monday'`**
   (`card/build/[step]/+page.server.ts:219`). A Sunday-start person previews weekly squares as if
   weeks start Monday. Possibly invisible, because a fresh card has no check-ins. Unverified.
2. **Test clock ignored.**
   - `me` (`changePassword`, `setPassword`: `retireResetLinks(…, new Date())`) and `admin`
     (`listInvites(db, new Date())`) ignore `TEST_CLOCK`.
   - Harmless in production, inconsistent in E2E.
3. **Two clock reads per action.** The `groups/[id]` actions read `requestNow` twice (membership
   check, then action), at two instants. That's negligible, but the second read could fall in a
   different day than the check.
4. **Sequential loads (performance, not a bug).** The `groups/[id]` load awaits `listMembers`,
   `groupFeed` and `groupBoard` one after another. They are independent.

## New helpers

```ts
// lib/server/request.ts
export function requireDb(unavailable: string): Db; // error(503, unavailable) when unconfigured
export function personOf(user: { timezone?: string | null; weekStartsOn?: string | null }): {
	timezone: string; // ?? 'UTC'
	weekStartsOn: WeekStart; // 'sunday' stays, anything else → 'monday'
};
export function requestClock(cookies: Cookies): Date; // requestNow(cookies, TEST_CLOCK)
export function formText(form: FormData, key: string): string; // string value or '' (no trim)
export async function readForm(request: Request): Promise<(key: string) => string>;

// lib/server/log.ts
export type LogLine = LogEntry | { level: 'error' | 'warn'; source: string; message: string };
export function log(line: LogLine): void; // console[level](JSON.stringify(line)), keys as given
```

No `requestContext(event)`. The four helpers are each one line at the call site, and a context
object would hide which page needs what.

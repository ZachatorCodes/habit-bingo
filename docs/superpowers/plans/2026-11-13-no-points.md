# Remove points Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace points with per-square completion and % complete everywhere, rank the monthly
leaderboard by % complete, and drop the all-time board and the saved points column.

**Architecture:**

- In `src/lib/game/score.ts`, `squarePoints` becomes `squareCompletion` (0–1), and `scoreCard`
  loses `points`. The game-level `rankRows` sorts by percent, then lines, then name.
- The server leaderboard keeps only the month board.
- Migration `0014` drops `month_result.points`.
- The UI drops every points display.

**Tech Stack:** SvelteKit 2 / Svelte 5, Drizzle + PGlite, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-no-points-design.md`

## Global Constraints

- Strict TDD.
- `src/lib/game` keeps 100% coverage.
- Never run `npm run dev`, `db:migrate` or `db:studio`, and never read `.env*`.
- Generate migrations with `npm run db:generate -- --name <name>` (offline).
- **Naming:** `evaluateSquare` already returns `progress` (the ring fill), so the new per-square
  value is named **`completion`** everywhere, never `progress` or `points`.
- No "pts" or "points" text left in the UI or README (except "points" in unrelated prose, e.g. auth
  comments).

## Review Focus

1. **A weekly limit above 0** ("at most 3 a week"): a day is within it while that week's running
   total, up to that day, is ≤ 3. The week is clipped to the card, using `weekStartsOn`.
2. **Card started mid-month:** the limit and daily denominators are the days on the card.
3. **A won-back lost square** (logging the missed day) restores its completion.
4. **Leaderboard ties:** an equal % and equal lines share a rank, ordered by display name A–Z.
   Members with no card stay unranked, at the bottom.
5. **History rows saved before this change:** they read fine without points (the column is gone,
   nothing selects it).

### Task 1: Game rules

**Files:**

- Modify: `src/lib/game/score.ts`, `src/lib/game/leaderboard.ts`.
- Test: `score.spec.ts` and `leaderboard.spec.ts` (create if missing).

**Interfaces:**

- Produces:
  - `squareCompletion(rule, span, counts, today, state): number` in `[0, 1]`. It replaces
    `squarePoints`.
  - `CardScore = { counting: number; percent: number; lines: number[][]; tiers: Tier[] }`.
  - `scoreCard(size, squares: { completion: number; counting: boolean }[])`, with
    `percent = Math.round(100 * Σcompletion / CARD_SIZES[size].habits)`.
  - `rankRows<T extends { percent: number | null; lines: number | null; displayUsername: string }>(rows)`.
    - Order: percent desc, then lines desc, then `displayUsername` A–Z (`localeCompare`).
    - Rank: competition rank over equal `(percent, lines)`.
    - Rows with `percent: null` are unranked and come last, in input order.
- Completion rules (spec §Rules):
  - `state === 'lost'` → 0, for every kind of square.
  - Monthly goal, daily habit and weekly habit: the old `squarePoints` formulas ÷ 10.
  - **Any limit:**
    - completion = finished card days within the limit ÷ days on the card;
    - finished means `d <= min(today − 1, monthEnd)`;
    - within: `target === 0` → `count(d) === 0`; `period === 'day'` → `count(d) <= target`;
      week → `progressBetween(rule, counts, weekStart(d), d) <= target`, with the week from
      `clippedWeeks(rule, startDate, weekStartsOn)`; month →
      `progressBetween(rule, counts, startDate, d) <= target`.
